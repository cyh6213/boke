广告机审质量运营实习

围绕广告机审策略搭建和异常治理做 AI 提效。在真实业务中，我关注的不只是单个 Agent 能否完成任务，而是多个平台、权限限制和人工节点共同存在时，流程如何持续向前推进。

岗位方向：广告机审运营 工作重点：Agent 应用与流程自动化 经历时长：一个多月
2 条异常治理与策略搭建两条工作主线
Skill → Multi-Agent从单点能力沉淀到流程级协作
1 周 → 2 天单条策略搭建周期的业务记录
01 / ROLE

角色不是开发底层平台，而是在真实业务里验证 Agent 如何提效

CQC 的广告机审工作需要为短视频、广告等内容搭建机审策略与 Workflow，并持续处理误判 Case 和效果问题。我主要承担 AI 提效相关工作：把重复、繁琐、需要跨平台推进的任务拆解为可复用能力，再重新组织人与 Agent 的协作关系。

02 / WORK STREAMS

实际工作分为异常治理自动化与策略搭建自动化

两条主线分别解决“问题如何更快被发现和响应”以及“新策略如何更少依赖人工推进”。

工作主线 A

异常治理自动化

日常需要监控机审误判情况，并接收线上暴露的误判 Case。针对人工巡检和重复排查成本，搭建“定时巡检主动预警”与“群聊消息被动响应”两条链路，帮助更早发现问题并聚合处理入口。

工作主线 B

策略搭建流程自动化

策略搭建涉及资料查找、配置、审查、跨平台流转和人工审批。由于权限与安全约束，它无法完全自动化，重点因此转向自动推进可自动化部分，并为人工节点准备足够上下文。

03 / BUSINESS WORKFLOW

真正耗时的不是某一步，而是步骤之间反复等待和整理上下文

每个环节都可以借助工具或 Agent 提效，但如果仍由人记住状态、切换平台、复制结果并通知下一环节，人实际上仍在承担流程调度器的职责。

资料查询收集规则、案例与已有策略
策略搭建组织判断逻辑并完成配置
结果审查检查格式、质量与覆盖情况
跨平台流转在不同系统间传递结果
人工节点处理权限、安全与关键判断
04 / AGENT EVOLUTION

从单点 Skill，演进为主控 Agent 负责流程推进

第一阶段先梳理策略搭建所需能力并沉淀为独立 Skill，解决单点提效。实际使用后发现，单点能力并没有消除人和 Agent 的双向等待，因此继续向流程级协作演进。

第一阶段

多个独立 Skill

每个 Skill 解决一个具体步骤，但需要人工选择下一项能力、传递上下文并检查结果。

→
第二阶段

主控 Agent + 多子 Agent

主控负责理解任务、维护上下文和推进流程；子 Agent 复用已有 Skill；人只在权限、安全或关键判断节点介入。

1 周 → 2 天

材料中记录的结果是单条策略搭建周期由一周缩短到两天。该数据用于说明流程组织方式带来的效率变化，不扩展为机审准确率或整体业务收益。

05 / REAL CONSTRAINTS

真实落地首先受权限和平台能力约束，然后才是模型能力

这段经历修正了我只从模型能力出发看 Agent 的视角。在办公和运营场景中，Agent 是否能完成动作，往往先取决于系统是否开放能力、权限是否允许以及人工节点能否被清晰组织。

权限边界

部分操作因权限与安全要求必须由人完成，不能为了自动化绕过业务控制。

平台可操作性

平台是否提供稳定接口和可被 Agent 调用的能力，决定自动化链路能走多远。

Agent 能力

在前两项成立后，检索、办公操作和上下文处理能力才决定执行质量与效率。

06 / RESULT & BOUNDARY

公开结果，也主动说明不能从材料中推出什么

能够确认的是两条自动化链路、Agent 协作方式的演进，以及单条策略搭建周期变化。页面不使用岗位分析中的模拟数据，也不把个人项目功能写成公司内部已经部署的能力。

经历边界：岗位长期核心仍是基于 Skill 和现有 Agent 平台完成运营提效，并围绕机审效果等业务指标持续优化。部分流程受权限与安全约束，不能完全自动化；目前没有公开误杀率、召回率或整体人效等更广泛指标。
07 / REFLECTION

这段经历最重要的产出，是建立了真实业务中的工程判断

01

个人项目可以证明方案能够运行，但只有真实流程会暴露权限、跨平台协作和人工决策这些无法靠想象补齐的约束。

02

Agent 提效不只是增加 Skill。单点能力越多，如果缺少统一的流程推进和上下文组织，人仍然会成为隐形调度器。

03

这段经历也帮助我确认长期方向：希望继续做 Agent 工程开发，深入参与代码实现、Agent 策略、工具调用和运行时稳定性建设。
