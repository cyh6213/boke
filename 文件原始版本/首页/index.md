### Workflow — 可视化任务编排与执行系统

针对 LLM Agent 执行路径不可控、易出现跳步和遗漏的问题，通过 DAG 规划与执行解耦，保证执行路径固定化与可见即所得。

> 💡 **应用场景举例**
>
> 这套系统可以用在测试场景。比如测试 RAG 系统的回答质量，需要验证 60 条测试数据，传统做法让 Agent 去跑，它可能会偷奸耍滑——发现前几条和后面几条类型相似，就直接复制结果，最终只跑了 30 条就说完成了。但在 Workflow 中，DAG 图定义了 60 个独立节点，执行引擎强制按图执行，不存在"跳过"的可能。

### Tree — Workflow 3.0（进行中）

Workflow 3.0，将 DAG 多层树结构应用于长链路 Agent 任务，解决上下文溢出、遗忘漂移、错误累计等问题。目前仍在开发中。

**项目来源**

在开发长链路 Agent 的过程中，发现它们普遍存在推理漂移、任务遗忘、上下文溢出等问题。核心思路是把 Workflow 的 DAG 图改造成多层树结构——外层做摘要保留任务全貌，内层保留执行细节，让 Agent 既能看见全局又不会丢失关键信息。

## 思考（Notes）

> 💡 **关于 RAG 的思考**
>
> 在经历了阶段四之后，我发现 RAG 目前的主流使用场景其实就是客服类场景，但这些场景有一个共同特点：对响应时间和成本都有一定限制。
>
> 这意味着我们能够实现的优化策略其实非常有限。比如智能路由需要对问题进行分类，多跳检索需要多次调用大模型和多次向量检索，将耗时有毫秒级增加到秒级。再比如分片优化中，有一种策略是对每个分片都调用大模型来压缩上下文，避免截断；还有 GraphRAG 可以提高全局问题的检索能力——但这些策略都需要多次额外调用大模型，成本太高，根本无法在客服场景中落地。
>
> 所以我就没有再进一步的研究向量 RAG 的相关优化，而是转向学习长期记忆的相关场景。
